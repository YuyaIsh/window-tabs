# Product specification

## 目的

Chrome、Notion、Claude、Terminal など、別々のデスクトップアプリのウィンドウをウィンドウ単位でひとつのグループとして扱い、上部の GUI タブから切り替えられるようにする。

対象アプリを Web 化したり、別プロセスの描画内容を `window-tabs` 内へ埋め込んだりはしない。対象ウィンドウは通常の OS ウィンドウとして動かしたまま、位置・サイズ・前面順を制御する。

Windows を先に実装し、macOS を後から同じ操作体系で追加する。

## 基本 UI

管理中のグループには、対象ウィンドウの上端へ密着するフローティングタブバーを表示する。

```text
[ 開発 ▼ ] [ Chrome ] [ Claude ] [ Notion ] [ + ]
```

- 左端: プリセット / グループ名
- 中央: 管理対象ウィンドウのタブ
- `+`: 開いているウィンドウを一覧から追加
- 1 ウィンドウだけになってもタブバーは残す
- グループを完全に解除した場合だけタブバーを消す
- タブバー自体は Alt+Tab / Task View / Mission Control の通常ウィンドウ一覧へ出さないことを目標とする

## グループの作成

### ウィンドウ D&D

通常のアプリウィンドウ同士を、修飾キーを押しながら D&D してグループ化する。

- Windows: `Ctrl + D&D`
- macOS: `Command + D&D`

挙動:

1. 修飾キーを押してウィンドウをドラッグする
2. 別の管理可能なウィンドウへ重ねる
3. ドロップ候補を視覚表示する
4. ドロップすると新規グループを作る、または既存グループへ追加する

Chrome のブラウザタブを通常操作で新しい Chrome ウィンドウへ分離しただけでは、自動的にグループへ追加しない。Google Meet など、一時的な別ウィンドウが勝手に混ざることを防ぐ。

### `+` から追加

タブバーの `+` から、現在開いているトップレベルウィンドウを一覧表示して追加できる。

同一アプリの複数ウィンドウは別項目として扱う。

```text
Google Chrome — GitHub
Google Chrome — Google Meet
Claude — 認証設計
Notion — Project A
Terminal — claude
```

D&D が使いにくい状況でも、ここから確実に追加できるようにする。

## タブ操作

- タブ選択: 対応する実ウィンドウを前面へ出す
- タブ D&D: グループ内で並べ替える
- 別グループのタブバーへ D&D: グループ間を移動する
- タブバー外へ D&D: グループから外し、独立ウィンドウへ戻す
- 1 タブだけになってもグループは維持する
- グループ解除は明示操作にする

## ウィンドウ配置

グループ内の実ウィンドウは、基本的にすべて同じ位置・サイズへ配置する。

非選択ウィンドウを最小化または画面外へ退避する方式は採用しない。選択中ウィンドウだけを前面へ出す。

理由:

- Windows Task View / macOS Mission Control で各実ウィンドウを個別に確認したい
- OS 標準のウィンドウ選択から管理対象を選んだ場合、そのまま対応タブへ同期したい

選択中ウィンドウをユーザーが移動またはリサイズした場合は、その位置・サイズをグループの新しい frame として扱い、他の管理対象ウィンドウも追従させる。

## OS 標準のウィンドウ切り替えとの同期

### Windows

Task View (`Win + Tab`)、Alt+Tab、タスクバー、通知などから管理対象ウィンドウが前面になった場合、対応するタブをアクティブ状態へ同期する。

Task View では、グループ内のウィンドウを 1 枚へ合成せず、それぞれ通常のウィンドウとして表示する。

```text
Task View

[ Chrome ] [ Claude ] [ Notion ]
```

Claude を選択した場合:

```text
[ Chrome ] [ Claude* ] [ Notion ]
```

### macOS

Mission Control、Command+Tab、Dock などから管理対象ウィンドウが前面になった場合も同じ考え方で対応タブへ同期する。

Mission Control では管理対象ウィンドウを個別表示する。

## 複数ディスプレイ

グループ単位で別ディスプレイへ移動できる。

操作:

- タブバー全体を別ディスプレイへドラッグする
- ショートカットから前 / 次のディスプレイへ移動する

移動時は管理対象の全ウィンドウとタブバーを同じディスプレイへ移す。

保存する位置・サイズは物理ピクセルではなく、対象ディスプレイの作業領域に対する割合で持つ。

```ts
type NormalizedFrame = {
  x: number;
  y: number;
  width: number;
  height: number;
};
```

ディスプレイが切断された場合は、グループを利用可能なメインディスプレイへ退避する。

## プリセット

プリセットは「保存済みの実ウィンドウ ID」ではなく、「どのウィンドウをこのタブへ接続するか」というルールとレイアウトを保存する。

```text
Preset
├─ name
├─ tabs
│  ├─ user-defined tab name
│  └─ window match rule
├─ tab order
├─ target display
└─ normalized frame
```

### プリセット適用

- 現在起動しているアプリ / ウィンドウだけを探索する
- 未起動アプリを勝手に起動しない
- 一致したウィンドウをタブへ接続する
- 見つからないタブは未接続状態で残す
- 後から一致するウィンドウが作られた場合は再照合できるようにする
- 候補が複数あり一意に決められない場合は勝手に接続しない

```text
[ Chrome ] [ Claude ] [ Notion ○ ]
                           未接続
```

未接続タブからは、候補ウィンドウの手動割り当てを行える。

## 同一アプリの複数ウィンドウ

プリセット上のタブ名と、実アプリのウィンドウタイトルは分離する。

```text
プリセット上の名前: AIチャット
実ウィンドウタイトル: 認証設計 — Claude
```

再接続では、OS から取得可能な情報を使って候補を絞る。

共通候補:

1. アプリ識別子
2. 文書 / パスなど、対象アプリが公開している識別情報
3. ウィンドウタイトルの部分一致または正規表現
4. OS 固有の補助属性
5. 前回のディスプレイ / 位置

OS 固有の補助属性例:

- Windows: executable path/name、window class
- macOS: bundle identifier、Accessibility で取得できる document / identifier

同じアプリで、タイトルも他の取得可能な属性も同一の場合は、再起動後に正確な識別はできない。その場合は未接続として手動で割り当てる。

誤接続を避けるため、位置や列挙順だけで自動確定しない。

## 再起動後の復元

OS 再起動や対象アプリ再起動後は、実ウィンドウの一時 ID が変わる前提にする。

復元は次の処理で行う。

1. 保存済みプリセットを読み込む
2. 現在存在するウィンドウを列挙する
3. 各 WindowRule と照合する
4. 一意に判定できるものだけ自動接続する
5. 不明なものは未接続で残す

macOS / Windows 自身が対象アプリのウィンドウを再起動後に復元している場合、その復元済みウィンドウへ再接続する。

`window-tabs` 自身が未起動アプリを開いたり、対象アプリのセッションを再生成したりはしない。

## 最小化・終了

### 最小化

- グループからは外さない
- タブは残す
- タブを選択した場合は復元して前面化する

### ウィンドウ終了

- 実ウィンドウとの runtime 接続を解除する
- プリセット由来のタブであれば、WindowRule は残して未接続状態にする
- 一時グループでプリセットに保存されていない場合は、そのタブを削除する

## プリセット作成

2 通り用意する。

### 現在のグループから保存

現在のタブ順、対象アプリ情報、識別候補、ディスプレイ、frame をプリセットとして保存する。

曖昧なウィンドウについては、保存時にユーザーがタブ名やタイトル条件を調整できるようにする。

### 空のプリセットを作成

アプリ / ウィンドウルールを手動で追加する。

ただし v1 では「現在のグループから保存」を優先し、空のプリセット編集 UI は後回しにしてよい。

## v1 で実装しないもの

- Web アプリへの置き換え
- 別プロセスの実ウィンドウを `window-tabs` の子ウィンドウとして埋め込むこと
- 対象アプリの自動起動
- Chrome 内部のブラウザタブ操作
- 自動タイルレイアウト
- ウィンドウのサムネイルプレビュー
- 同一属性しか持たない複数ウィンドウの推測による自動再接続
- macOS ネイティブ全画面 Space の制御

## v1 完了条件

Windows 10 / 11 上で次を満たすこと。

1. Chrome、Notion、Claude、Terminal などのトップレベルウィンドウをグループ化できる
2. GUI タブで選択ウィンドウを切り替えられる
3. 同一アプリの複数ウィンドウを別タブとして扱える
4. D&D と `+` の両方からウィンドウを追加できる
5. タブを並べ替え、別グループへ移動し、グループから外せる
6. 1 タブでもタブバーが維持される
7. グループを別ディスプレイへ移動できる
8. Task View / Alt+Tab から選択した管理対象へタブ状態が同期する
9. プリセットを保存できる
10. アプリ / PC 再起動後に、一意に識別可能なウィンドウへ再接続できる
11. 識別不能な候補を誤接続せず手動選択へ回せる
